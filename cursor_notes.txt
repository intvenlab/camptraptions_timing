## Telemetry decisions 2026-05-20
- Telemetry is RAM-first. Live state/current deadlines/current sequence fields stay RAM-only and are published over BLE.
- Persist only coarse lifetime telemetry counters in a separate `InternalFS` / LittleFS file; do not put telemetry into `DeviceConfig` or `CameraConfig`.
- Never write flash from ISR. ISR-safe paths may only update in-memory counters and set dirty/notify flags when a persisted counter actually changes.
- Flush telemetry snapshots later from normal code at controlled boundaries such as activity end, BLE disconnect, periodic dirty checks, or explicit app/test request.
- Target write budget is fewer than roughly 100,000 telemetry flash snapshots over board life; LittleFS wear leveling is acceptable for this project with rate-limited snapshots.
